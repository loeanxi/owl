# 缓存用量与钱包结算

预占时尚不知道缓存命中比例，仍按输入、缓存读、缓存写中的最高单价估算输入资金占用。最终用量可靠时，结算改用配置中各分量自己的单价；本次修复不修改费率或历史流水。

统一结算口径：`prompt_tokens` 是全部输入，已经包含缓存读取与缓存写入两个互不重叠的子集。普通输入等于总输入减去这两个分量。输入各分量费用相加后向上取整到分，输出费用另行向上取整。

- 标准 OpenAI/WorkBuddy/Grok 用量按上游响应提供的缓存子集计算，兼容已知 DeepSeek/Kimi 缓存字段；不接受请求参数中的用量或缓存提示。
- Anthropic 原生 `input_tokens` 不包含缓存读取、缓存写入。网关将三者相加一次，形成总输入，并保留读、写分量；流式和非流式一致。独立映射器的显式 `foldCacheTokens: false` 保留旧的原生输入口径，网关装配使用总输入口径。
- 没有缓存字段时按普通输入单价结算。缺失分量不宣称已确认缓存优惠，流水以空值保存未提供的指标。整个可选 `prompt_tokens_details: null` 没有提供缓存子字段，仍可按普通输入处理。
- 已明确提供的缓存计数字段为 `null`、负数、小数、非有限数、非安全整数，或缓存分量相互重叠、合计超过总输入时，保留 `REVIEW`，不猜测数量或自动退款。`0` 是合法读数。

只有适配器提供了可验证缓存分量的响应才能采用对应缓存价。SDK 桥、Gemini、Trae 等未提供这些细项的路径继续使用已转发输入的普通回退口径，本次不保证所有上游都支持缓存优惠。

历史流水不自动重算。历史缓存指标可能为空，费率、舍入和币种也可能不同；应先核对可关联的上游用量与当时收费规则，再单独处理账务。
