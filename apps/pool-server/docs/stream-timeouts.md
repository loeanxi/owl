# WorkBuddy 流式超时配置

WorkBuddy 默认使用空闲期限和总时长上限。收到任何上游响应字节（包括 SSE 心跳）会重新开始计算空闲时间；持续输出超过 120 秒的请求可以继续。连接尚未返回响应头时，同样受期限约束。

| 环境变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `OWL_POOL_WB_STREAM_IDLE_TIMEOUT_MS` | `120000` | 连续未收到上游字节时中止等待，单位毫秒。 |
| `OWL_POOL_WB_STREAM_MAX_DURATION_MS` | `600000` | 单次 WorkBuddy 流的总时长上限，单位毫秒；心跳不会延长此上限。 |
| `OWL_POOL_GATEWAY_UPSTREAM_TIMEOUT_MS` | 未显式设置 | 如果显式设置，仍作为 WorkBuddy 的绝对总期限，优先于上述总时长上限。其他上游适配器保留原有默认超时。 |

配置在 pool-server 启动时读取，修改后需要重新启动服务。空闲期限与总期限都会生效；显式绝对期限不会因持续输出而自动延长。

客户端取消会传递给 WorkBuddy 请求。超时、连接中断或取消发生在派发之后且无法确认最终用量时，预占进入 `REVIEW`，需要核对上游费用；不会因为客户端显示零用量而自动退款。确认未建立连接的临时失败仍可按已有路由规则重试。

流已经输出部分内容后发生错误时，网关会发送标准 SSE 错误帧，并保留错误原因和请求 ID，然后关闭流。错误不会被伪装成正常完成，也不会再仅显示“缺少结束原因”。

OpenAI Chat Completions 的受控超时、流中断错误会携带 `billing_state: "unknown"` 和明确错误代码。Owl 默认停止这些错误的请求级和任务级自动重试；用户明确配置的重试字符串、上游明确的 `x-should-retry` 指令仍保留原有覆盖语义。Anthropic 和 Responses 当前仅保证错误原因传播，尚未提供相同的未知费用重试标记。
