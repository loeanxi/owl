# 3. 推送 git push origin main # 常用变体 git merge --no-ff feature # 强制生成合并提交（即使可以快进） git merge --ff-only feature # 只允许快进，否则报错退出 git merge --squash feature # 把 feature 压成一个改动，不自动提交
merge 后的历史rebase 后的历史
黄金法则

rebase 只用于你自己独有的分支。绝对不对别人正在使用的公共分支 rebase——重写历史会让协作者的本地历史错乱。常见团队惯例：本地整理提交用 rebase，进主干用 merge 或 squash merge。

一句话记忆：merge 是"如实记录发生过什么"，rebase 是"把历史整理成希望它发生的样子"。
