# 工具按需发现

桌面会话保留精简的常驻工具。其余已注册能力通过 `tool_search` 发现并加载，下一次模型调用即可使用原生工具；未声明不代表插件被删除或能力不可用。闲聊和可直接回答的问题不触发发现，也不增加独立的模型意图分类调用。

## 从意图到步骤

主模型先识别目标，再将需要发现的能力拆成有明确动作的步骤：

- `capability`：能力领域，如图片编辑、网页研究或电子表格。
- `action`：要执行的动作，如去除背景、读取网页或创建表格。
- `target`：可选的处理对象。
- `constraints`：可选的字符串数组，列出必要条件，执行时仍需逐项核对。
- `query`：可选的补充检索词。

例如“查资料并整理 Excel”应区分搜索资料、读取来源和创建表格。发现多个步骤不会自动执行工作流，也不会替代步骤之间的数据传递、依赖关系和结果检查。按当前需要分批发现，避免提前加载后续所有工具。

```json
{
  "steps": [
    { "capability": "web", "action": "search", "target": "行业资料" },
    { "capability": "web", "action": "read", "target": "搜索结果中的来源页面" },
    { "capability": "spreadsheet", "action": "create", "target": "资料汇总表" }
  ],
  "limit": 4
}
```

`steps` 一次最多 4 项，所有步骤共享 `limit` 个新增工具名额，默认 4、上限 8。已有工具可出现在匹配结果中，不重复加载。仍可使用单个 `query` 搜索能力或确切工具名；`query` 与 `steps` 选一种输入形式。

## 候选的含义

`metadata_match` 只说明工具的注册元数据与步骤相符。它不表示操作已成功、外部服务可用、账号已经认证，或权限已经获批。模型应读取加载后的完整工具定义，检查动作、参数和必要条件，然后通过正常权限检查调用工具，并验收实际结果。

结果按步骤返回 `status`：`metadata_match` 表示元数据匹配；`refine` 表示需要细化，弱候选不自动加载；`no_match` 表示当前检索未命中；`budget_limited` 表示本次加载预算不足。`candidates` 给出候选及缺口，`uncheckedConstraints` 列出尚未确认的条件。

弱相关或缺少动作证据时，根据缺口细化动作、补充对象、改用目录名称或中英文别名重搜。也可用明确的 `query`（如 `edit_image`）加载完整 schema 检查条件；加载本身不能证明支持透明通道等细节。工具定义不支持某个条件，与账号未认证或 API 暂不可用是不同限制，应分别检查。一次未命中不足以宣布系统没有该能力；仍无法确认时准确报告限制，不能虚构执行结果。

发现依据是本地工具名称、说明和参数等元数据，不是外部服务的实时能力证明，也不保证自然语言查询完全命中。插件应写清支持的动作、对象、限制及参数说明，避免只使用“多功能助手”一类泛化描述。

## 上下文与权限

每次发现使用有上限的工具预算，复杂任务不会按步骤数无限放大加载量。完整工具 schema 按需加入后续调用；常驻目录只用于指引发现。原生调用保留图片和结构化结果，继续遵守已有工具权限、审批和验收机制。
